# שלב 22: נגן Rubinny ב-Microsoft Store (Windows 10 ומעלה)

**סטטוס:** תוכנית, ממתינה לאישור.

## 1. מטרה

להפיץ את אפליקציית המחשב הקיימת (Electron, ‏`apps/desktop`) דרך Microsoft Store, כך שמנהל מסכים יוכל להתקין את הנגן על כל מחשב Windows 10 או 11 בלחיצה. העדכונים יגיעו אוטומטית מהחנות.

**מה לא משתנה:** הנגן עצמו, השרת וה-CMS. זו חבילה והפצה חדשות לאותה אפליקציה. המתקין הקיים (NSIS, ‏`.exe` ב-GitHub Releases) נשאר למי שמתקין בלי החנות.

## 2. היתרונות לעומת המתקין הקיים

|                   | מתקין `.exe` היום   | Microsoft Store           |
| ----------------- | ------------------- | ------------------------- |
| אזהרת SmartScreen | כן (המתקין לא חתום) | לא: החנות חותמת על החבילה |
| עדכונים           | ידני                | אוטומטי מהחנות            |
| התקנה בארגון      | הורדה מ-GitHub      | חנות, ‏winget, ‏Intune    |
| עלות חתימת קוד    | תעודה בתשלום כל שנה | אין צורך בתעודה           |

## 3. החלטות טכניות

### S1. פורמט: חבילת MSIX (מומלץ)

- **מה:** חבילת MSIX (`.appx`/`.msix`) שנבנית עם `electron-builder` (target ‏`appx`), שכבר משמש את הפרויקט.
- **חתימה:** החנות חותמת על החבילה בעצמה בזמן ההגשה. לא צריך לקנות תעודת חתימת קוד.
- **חלופה:** הגשת ה-`.exe` הקיים כ"אפליקציית EXE/MSI". מחייבת מתקין חתום בתעודה מסחרית (עלות שנתית), והעדכונים לא עוברים דרך החנות. לא מומלץ.
- **מגבלה:** ה-target של MSIX ב-electron-builder מסומן beta בתיעוד שלו. ה-target ‏`appx` הוא הוותיק ומתאים לחנות. דורש אימות בבנייה בפועל.

### S2. גרסאות Windows

- **מינימום:** Windows 10 גרסה 1809 (build 17763) ומעלה, וכל Windows 11. Electron 44 תומך ב-Windows 10 ומעלה בלבד.
- **ארכיטקטורות:** x64, ו-arm64 למחשבי ARM (Surface וכדומה). חבילה אחת לכל ארכיטקטורה, או bundle.
- **דורש אימות:** הגרסה המינימלית המדויקת שהחנות מקבלת לחבילות Desktop Bridge, ושה-Electron הנוכחי רץ עליה.

### S3. הרשאת runFullTrust

כל אפליקציית Electron ב-MSIX צריכה את ההרשאה המוגבלת `runFullTrust`. החנות תבקש הסבר בזמן ההגשה: "אפליקציית Win32 (Electron) שלא יכולה לפעול בלעדיה". היו מקרים שבהם נדרשה פנייה לתמיכה כדי לאשר אותה. זה סיכון של זמן, לא של קוד.

### S4. התאמות קוד באפליקציה

| נושא                   | היום                   | ב-MSIX                                                                                                |
| ---------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------- |
| הפעלה עם עליית Windows | `setLoginItemSettings` | לא עובד באפליקציה ארוזה. צריך הרחבת `StartupTask` במניפסט. דורש אימות מול התיעוד של electron-builder. |
| שמירת כתובת השרת       | `userData`             | עובר אוטומטית לתיקייה וירטואלית של החבילה. בלי שינוי קוד, רק בדיקה.                                   |
| מצב קיוסק ומסך מלא     | כן                     | ללא שינוי. צריך לוודא שיש דרך יציאה ידועה (`Ctrl+Shift+Alt+Q`), גם בגלל מדיניות החנות.                |
| מניעת שינה             | `powerSaveBlocker`     | ללא שינוי.                                                                                            |
| זיהוי חבילה            | —                      | `process.windowsStore` של Electron, כדי לבחור את מנגנון ההפעלה האוטומטית המתאים.                      |

### S5. בנייה ב-CI

- **בנייה:** משימה חדשה ב-`release.yml` על `windows-latest` שבונה `.appx` לחנות, עם זהות החבילה מ-Partner Center (שם ו-Publisher).
- **זהות החבילה:** הערכים נשמרים כמשתני repo (לא סודות: הם ציבוריים בחבילה).
- **בדיקה:** בדיקת המניפסט (גרסה מינימלית, הרשאות, StartupTask) והתקנת בדיקה עם חתימה זמנית על runner של Windows, אם אפשרי.
- **הגשה:** ידנית ב-Partner Center בהתחלה. אוטומציה דרך ה-API של Partner Center אפשרית בהמשך.

## 4. מה צריך ממך (לא אפשרי מכאן)

1. **חשבון מפתח ב-Microsoft Store:**
   - **חשבון פרטי:** לפי ההודעה של Microsoft מספטמבר 2025, הרשמה ללא תשלום, עם אימות זהות, דרך storedeveloper.microsoft.com.
   - **חשבון חברה:** במקורות מופיעים גם $99 חד-פעמי וגם פטור מהתשלום. דורש אימות מול התיעוד הרשמי.
   - **שם המפרסם בחנות:** שם המפרסם שיופיע בחנות נקבע לפי החשבון.
2. **שמירת שם האפליקציה** ב-Partner Center (למשל "Rubinny Player"), והעתקת ערכי הזהות: Package Identity Name ו-Publisher.
3. **תוכן לדף בחנות:**
   - **תיאור:** בעברית ובאנגלית. אני אכין טיוטה.
   - **צילומי מסך:** מהסקריפט הקיים.
   - **אייקונים:** בגדלים הנדרשים.
   - **קישור למדיניות הפרטיות:** כבר קיים כטיוטה.
   - **שאלון דירוג גילאים (IARC).**

## 5. אבטחה, פרטיות ונגישות

- **אבטחה:** אותן הגנות של היום (ניווט רק לשרת שהוגדר, חסימת IPC). MSIX מוסיף בידוד של מערכת הקבצים והרישום, והתקנה והסרה נקיות.
- **פרטיות:** האפליקציה לא אוספת מידע ולא כוללת telemetry. בדף החנות צריך להצהיר על כך. הנגן מתחבר רק לשרת שהמשתמש הגדיר. החנות עצמה אוספת נתוני התקנה (Microsoft היא המעבדת). כדאי לציין זאת במדיניות הפרטיות.
- **נגישות:** מסך ההגדרה הראשוני (הזנת כתובת השרת) נבדק כבר עם axe. בחנות צריך לוודא שגם מקלדת וקורא מסך עובדים בו.
- **רישוי:** האפליקציה ברישיון AGPL-3.0, עם קישור לקוד המקור באפליקציה ובדף החנות. ההתאמה בין תנאי החנות (Microsoft Store App Developer Agreement) ל-AGPL ולרישיונות של רכיבי צד שלישי: **דורש בדיקה משפטית.**

## 6. שלבי עבודה

1. **22.1 קוד:** זיהוי ריצה כחבילה, הפעלה אוטומטית דרך StartupTask, בדיקות יחידה.
2. **22.2 בנייה:** target ‏`appx` ל-x64 ול-arm64, מניפסט, אייקונים בכל הגדלים, משימה ב-CI, ובדיקת התקנה על Windows ב-CI.
3. **22.3 דף החנות:** טיוטת תיאור בעברית ובאנגלית, צילומי מסך, עדכון מדיניות הפרטיות, ומדריך הגשה צעד-אחר-צעד ב-`docs/MICROSOFT-STORE.md`.
4. **22.4 הגשה:** אחרי שתפתח את החשבון ותעביר את ערכי הזהות: בנייה עם הזהות האמיתית, הגשה (אתה ב-Partner Center, עם המדריך), תגובה להערות הבודקים, ושחרור כ-0.12.0.

## 7. בדיקות

- **אוטומטי:** יחידה לקוד החדש, בדיקת מניפסט, והתקנה והפעלה של החבילה על runner של Windows.
- **ידני (אצלך או אצל משתמש):** התקנה מהחנות על Windows 10 ועל Windows 11, הפעלה מחדש של המחשב (עלייה אוטומטית), עדכון גרסה דרך החנות, והסרה.

## 8. סיכונים

- **אישור runFullTrust:** עלול לעכב את ההגשה (S3).
- **אישור הבודקים:** מוצר קיוסק במסך מלא. החנות עלולה לבקש הבהרות. דרך היציאה וההסבר במסך ההגדרה יעזרו.
- **אין לי מחשב Windows אמיתי:** הבדיקה כאן היא רק ב-CI. נדרשת בדיקה ידנית על מכשיר.
- **beta:** תמיכת MSIX ב-electron-builder (S1).
